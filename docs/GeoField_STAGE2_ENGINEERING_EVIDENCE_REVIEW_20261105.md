# GeoField 2번 — L-브래킷 공학 분석 근거 보완

기준: 원본 L-브래킷 STEP 하나. Windows 실사용 최종 검증은 **모든 개발이 끝난 맨 마지막에 한 번만**. 기존 STEP·CalculiX INP/STA/FRD·SQLite·ML 가중치 및 기록 불변. 외부 유료 AI 자동 호출 금지.

## 이번에 실제 구현한 사항

1. **3개 메시의 응력·변위 변화 방향**: 세 실제 CalculiX 계산을 독립 재검증한 결과에서만 증가·감소·비단조 추세를 계산. 원본 수치 및 2→3 변화율과 함께 결과 화면/HTML 보고서에 추가. 3개 값만으로 완전 수렴이나 재료 안전을 선언하지 않음.
2. **기존 5% 민감도 기준 재해석**: 원본 INP에서 실제 메시 세분화·하중 및 모멘트 비교가 통과한 경우에만 5% 선별 기준 충족 여부를 참고용으로 설명. 세분화·하중 조건이 다르면 '메시만의 변화'라고 주장하지 않음. 수치 안정성 5% 선별 통과도 수렴 인증 아님.
3. **실제 FRD 표면 최고응력 위치 이동**: 3개 실행의 최고 좌표와 이동 거리를 표시. 서버가 제공한 mm 이동 거리와 실제 세 좌표의 유클리드 거리 재계산이 어긋나면 위치 진단 부분만 비표시(원본 응력·변위는 보존). 미세 메시 목표 크기와의 비교는 추가 점검에 대한 신호일 뿐 '동일 CAD 면·결함' 또는 '위치 수렴' 증명 아님.
4. **홀/필렛 원인 귀속**: 기존 로컬 OCP는 원통형 면의 관통/막힘 분류를 할 수 있지만, FRD 노드 ↔ 정확한 OCP 홀·필렛 면 매핑 근거는 없음. 그러므로 '해당 홀 때문이다'는 자동 결론을 차단하고 결여된 원인 근거를 보고서에 기재.
5. **재료·안전율**: 기존 UI 프리셋은 영률 E 및 포아송비 ν이지 항복강도나 허용응력 자료가 아님. 임의의 강재 항복강도나 안전율을 생성하지 않고, 출처·온도·규격·하중·경계조건·반력과 함께 입력 근거가 있어야 후속 안전율 계산이 가능함을 표시.
6. **ML 정확도**: BrepMFR/R12 연구 추론 완료와 독립 정답 데이터로 측정된 정확도를 분리. 독립 라벨/테스트셋/혼동행렬/재현 가능한 성능평가 없이 예측 점수를 정확도·보정 확률로 표시하지 않음.

## 코드 연결

- `src/payload/frontend/cad.js`: `gfEngineeringStage2Review` (읽기 전용), Results `gfEvidenceChecklistLines` 및 HTML `gfAppendEvidenceScope` 공유.
- `gfFetchMeshFollowup`: 기존 별도 서버 재검증을 통과한 현재 CAD/실행 ID/조건 SHA/연구 ID의 데이터만 받으며, 표면 이동 거리와 좌표 간 실제 거리를 재대조.
- `src/tests/test_step2_engineering_evidence_review.js`: 비단조 추세, 수치 선별/하중 불일치, 공간 위치 변동·모순, 물성/ML 근거 누락 차단.
- 기존 CAD/FEA/ML/AI 계산/모델 호출 과정에 **새 자동 계산이나 유료 요청을 추가하지 않음**.

## 검증·후속 한계

이 단계는 기존 3회 실제 솔버의 **근거 사용·해석 해설 품질**을 높인다. 정확한 CAD 면 귀속, 전문 구조안전 승인, 항복강도 기반 안전율 및 독립 ML 성능 점수 생성은 아직 완료되지 않음. 그런 결과가 필요하면 검증 가능한 추가 자료와 실제 분석 알고리즘부터 갖추어야 한다. 실제 사용자 Windows 환경·원본 L-브래킷은 마지막 통합 검수 전까지 실행하지 않는다.
