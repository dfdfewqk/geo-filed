# GeoField — 최종 Windows 1회 통합 검수 기준 (2026-11-05)

> 상태: 검수 **절차 문서**. 사용자 Windows 원본 STEP을 성공적으로 검수했다는 증빙이 아닙니다.
> 원칙: 새로운 기능/형상 확장보다 *현재 원본 L-브래킷*의 원클릭 정확도·안전성·사용성을 우선합니다.

## 0. PC 검수 전에 코드·CI로 끝낼 작업

- [ ] 단계 1~5의 CAD/FEA/ML/메시/로컬 AI/HTML 보고서/SQLite 비교 연결 코드를 최신 작업 브랜치에서 검토
- [ ] 원본 STEP SHA, FEA 실행 ID, 조건 SHA, 3개 메시 연구 ID, SQLite 스냅샷 ID의 교차 식별 확인
- [ ] CAD/FEA 변경 후 오래된 3D·보고서·AI·비교를 표시하지 않는 회귀 검사
- [ ] 메시 실행 중 버튼과 보고서/유료 AI 요청을 차단하고 종료 후 재활성화하는 회귀 검사
- [ ] ML 추론 성공/실패/비활성화 상태를 FEA 근거와 혼동하지 않는 검사
- [ ] 보고서 AI OFF에서 **외부 유료 API 0회**이고 ON도 사용자 명시 동의 기반 단일 요청인 검사
- [ ] Python 3.13/Windows 시작 CMD/복원/기존 데이터 비파괴 호환성 및 Linux/Windows CI 통과
- [ ] 실패 항목은 코드 수정 후 CI에서 해결. **사용자에게 중간 PC 테스트 요청하지 않음**

## 1. 사용자 Windows에서 단 한 번의 통합 검수

1. 현재 정상 보관 데이터(기존 STEP, SQLite, ML 모델·가중치, 사용자 설정, 기존 실행 결과)를 **별도 위치에 백업**하고 해시/폴더 변경 여부를 확인한다.
2. 최신 후보를 **별도 새 폴더**에 압축 해제한다. 기존 설치본을 덮어쓰거나 해시 확인을 우회하지 않는다. 기존 Windows 시작/업그레이드 도구의 명시적 승인·롤백 규칙을 지킨다.
3. 기존에 사용하던 **원본 L-브래킷 STEP 하나만** 불러온다. CAD SHA, 치수, 외곽 3D 표시, 실제 원본과 선택된 파일의 일치를 확인한다.
4. 사용자에게 이미 확정된 **재료·고정면·하중면·하중값·방향**을 그대로 사용한다. 기존과 달라지면 새 실험이므로 이전 수치와 개선 효과를 주장하지 않는다.
5. 메인 **결과 분석**을 **딱 한 번** 클릭한다. 자동 조건 저장·실제 기본 Gmsh/CalculiX FEA·독립 INP/STA/FRD 검증·연속 3회 메시 연구의 종료 상태를 확인한다. 메시/결과가 확정되기 전에 추가 실행 버튼을 누르지 않는다.
6. 결과 화면에서 검증된 최대 von Mises/변위, FRD 표면 최고응력 좌표, 3회 메시별 수치·좌표 변화, R12/BrepMFR의 **실행 상태와 정확도 미검증 안내**, 로컬 AI 규칙 설명을 확인한다. 표시 한계·메시 수렴·구조 안전을 검증 완료로 오기하지 않는다.
7. **외부 AI OFF** 상태로 HTML 통합 보고서를 열고, CAD/FEA 실행/조건 SHA·메시 연구 결과·모든 미검증 이유가 일관되는지 확인한다. 보고서 열기가 추가 FEA 계산을 시작하면 실패다.
8. 기존의 신뢰 가능한 과거 **같은 STEP** FEA 기록 하나를 선택하고, SQLite 원본 재검증 후 현재 계산과 응력·변위·재료·하중·고정 조건이 읽기 전용으로 비교되는지 확인한다. 다른 STEP은 자동 비교하지 않는다.
9. 프로그램 종료/재시작 후 기존 SQLite/ML/STEP 기록이 남아 있는지 확인한다. 위험한 자동 복원, 강제 덮어쓰기, 이전 수치의 현재 실행 승격이 없어야 한다.
10. 성공/실패를 **한 건의 검수 기록**으로 수집한다: 실행 SHA, 사용한 STEP 해시, 시작/종료된 계산 ID, 솔버 로그, 검증 결과, 보고서 생성 상태, 최종 화면, 백업 보존 여부. 샘플 D6 CI 실험 수치를 사용자 원본의 실측으로 대체하지 않는다.

## 2. 실패 시 무조건 재실행하지 않는다

- 상태 조회 실패·서버 종료 불명·결과 파일 검증 불일치 시 **원본 계산 ID로 상태와 로그만 조회**한다. 솔버가 계속 실행 중일 수 있으므로 동일 해석을 중복 시작하지 않는다.
- 정확한 실패 구간(원본 CAD / FEA / 메시 / ML / 로컬 AI / 보고서 / SQLite 비교 / 재시작)과 에러 문자열을 기록한다.
- CI로 재현 가능한 문제는 **GitHub 코드·자동테스트를 먼저 고친 뒤** 다음 허가된 실사용 검수에서 확인한다.
- 모든 검사 결과와 무관하게 구조 안전 인증, 항복강도 기반 안전율 또는 홀/필렛 응력 원인 확정은 독립적인 물성·하중·반력·메시 검증 없이 만들지 않는다.

## 3. 완료 판정

**코드/CI 완료**와 **사용자 Windows 실사용 통과**는 별개다. 사용자 PC의 1회 통합 검수에서 주요 흐름, 보존, 보고서와 기록 비교까지 확인될 때만 GeoField의 운영 흐름을 완료라고 표시한다. 구조 안전성과 ML 정확도는 별도 검증 근거가 없으면 정확하게 미검증으로 표시한다.
